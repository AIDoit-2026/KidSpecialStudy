## 1. 目标与非目标

### 1.1 一句话目标

家长给孩子建好档案、选好教材册次后，孩子每天打开就能看到**一份 30 分钟内可完成的组合任务**（认字 + 拼音 + 数学 + 写字），做完打卡、攒星星；家长只需拍照批改写字和看周报。

### 1.2 设计约束（来自需求）

| 约束 | 落地含义 |
| --- | --- |
| 每日 ≤ 30 分钟 | 任务总量硬上限 30 分钟，超时自动收尾（可续做但不计入当日） |
| 知识点来自当前教材 | 内容按「册次 → 单元 → 课时 → 节点」组织，与人教版目录一一对应 |
| 重点参考"练一练" | 题目原型取自教材练习，再做变式，不另起体系 |
| 每单元拆多个 30 分钟节点 | 一个节点 = 一次完整打卡任务，单元进度以节点计 |
| 数学重在应用/看图题 | 计算题占比 ≤ 20%，题型以情境应用题、看图列式、比多比少、逆向思考为主 |
| 写字 3~5 字/天，家长拍照评分 | 田字格示范 + 拍照上传 + 家长多维评分，形成书写成长曲线 |
| 多孩子、数据隔离 | 所有数据以 `kidId` 为命名空间，切换孩子数据互不可见 |
| 纯单机、浏览器内存储 | 无后端、无账号、无云同步；数据落地 localStorage + IndexedDB |
| 可导出进度 | 支持 JSON 全量、CSV 打卡流水、ZIP（含作业照片）三种导出，并支持导入还原 |

### 1.3 明确不做

- 不做云同步 / 多设备实时共享（只做"导出→导入"离线迁移）
- 不做 AI 自动批改写字（v1 由家长评分，AI 评分列为 v2 可选项）
- 不做社交、排行榜、家长社区
- 不做直播课 / 视频讲解（只做文字 + 语音提示）
- 不做自动出题（题目全部预生成入库，保证可控、可审、离线可用）

### 1.4 成功标准

1. 首次使用 3 分钟内能建好档案并开始第一天任务；
2. 一年级孩子**不识字也能独立完成**（题干全部可语音朗读）；
3. 单日实际耗时中位数 ≤ 28 分钟；
4. 家长每日批改 + 查看耗时 ≤ 3 分钟；
5. 连续使用 4 周不出现数据丢失、进度错乱；
6. 换设备时用导出包能在 1 分钟内完整还原。

## 2. 参考项目「宝贝学习乐园」复用评估

### 2.1 现状盘点

| 项 | 现状 |
| --- | --- |
| 形态 | 单文件 HTML，约 642 KB，6668 行，内联全部 CSS/JS |
| 页面 | 首页、拼音乐园、古诗花园、认识汉字、数字王国、逻辑挑战、闯关冒险（7 个模块页） |

| 激励 | 星星 / 等级 / 徽章 |

| 冗余 | 文件里混有 `data-page-node-id` 编辑器痕迹；还存在一段云端 database 同步逻辑 |

### 2.2 可直接复用（省 30% 工作量）

- **设计令牌**：`--pink #FF6B9D` / `--blue #4ECDC4` / `--yellow #FFE66D` / `--green #95E67E` / `--purple #C47AFF`，圆角 16px，卡片阴影 `0 4px 15px rgba(0,0,0,.08)`；
- **双端布局骨架**：`.sidebar` + `.bottom-tabs` + `.main-content` + `@media (max-width:768px)` 断点；
- **多孩子 Storage 封装**：`readRaw/writeRaw/getData/setData/getKidData` 这一套命名空间思路直接沿用（前缀改为 `wb2_` 避免与旧项目冲突）；
- **TTS 播报封装**（去掉 base64 音频，改用 `speechSynthesis`，包体可瘦身 300 KB+）；
- **星星/等级/连续天数** 激励层逻辑。

### 2.3 必须重做

| 模块 | 原因 |
| --- | --- |
| 数据模型 | 旧项目是"积分型"（只有 stars/levels），新项目要"流水型"（每道题、每次打卡都可追溯、可导出） |
| 图片存储 | localStorage 上限约 5 MB，装不下作业照片 → 必须迁到 IndexedDB |
| 内容组织 | 旧项目题目硬编码在 JS 里，新项目要按册次/单元/节点组织成外部内容包 |
| 页面结构 | 从"6 个游戏模块"改为"今日任务 / 练习 / 写字 / 成长 / 家长中心"5 个主页面 |
| 云端同步 | 需求是纯单机，整段移除，改为导出/导入 |

### 2.4 结论

**不改造旧文件，新建骨架、复制其 CSS 与工具函数。** 旧文件里编辑器痕迹和 base64 音频占了大半体积，改造比重写更贵。

## 3. 用户与角色

| 角色 | 谁 | 关心什么 | 界面 |
| --- | --- | --- | --- |
| 孩子 | 6~8 岁，识字量有限 | 今天做什么、做完有没有奖励 | 大字号、大按钮、一次一题、全程可听 |
| 家长 | 家长本人 | 今天做完没、错在哪、写得怎么样、这周有没有进步 | 数据密集、可切孩子、可导出 |

采用 **人教版（统编）2024 年修订版**。该版自 2024 年秋季起在起始年级启用，逐年滚推（一年级 2024 秋、二年级 2025 秋、三年级 2026 秋）。

### 4.4 内容层级

```
册次 Book (yw-1a / sx-1a)
 └─ 学科 Subject (chinese / math)
     └─ 单元 Unit (u1..u8)
         └─ 节点 Node (n1..n6)   ← 一次 30 分钟打卡任务
             └─ 题目 Item        ← 最小判分单位
```

- **节点 = 一天**。节点内题目已排序（先认后练再应用），家长无需干预。
- 写字不进内容包：它由「写字表」全局有序队列驱动，每天取 3~5 字，按当天语文进度就近对齐。

### 4.5 题型清单（每类都给"为什么这么设计"）

**认字（5 题 / 约 5 分钟）**

| 题型 | 示例 | 判分 |
| --- | --- | --- |
| 看字选拼音 | 「山」→ shān / sān / shuān | 单选 |
| 选组词 | 「水」→ 水果 / 水车 / 山水（多选也支持） | 单选 |
| 选偏旁/部首 | 「明」的偏旁是 日 / 月 / 明 | 单选 |
| 数笔画 | 「火」有几笔 → 4 / 5 / 6 | 单选 |
| 形近字辨析 | 「日」和「目」哪个是"眼睛"的目 | 单选 |
| 字理配对 | 象形图 ↔ 汉字 | 连线 |

**拼音（6 题 / 约 6 分钟）**

| 题型 | 示例 | 说明 |
| --- | --- | --- |
| 认读选择 | 哪个是声母 "b" | 配语音朗读 |
| 标调 | "ma" 第三声标在哪 → mǎ / má | 声调位置 |
| 拼读合成 | b + ā → bā | 可朗读验证 |
| 整体认读判断 | zhi / zi 哪个是整体认读 | 概念辨析 |
| 前后鼻音 / 平翘舌 | an / ang、z / zh 听辨 | 依赖 TTS |
| 听音选字 | 读 "shān"，选「山」 | TTS 出题 |

**数学（5 题 / 约 11 分钟）—— 应用题与看图题为主**

| 题型 | 示例 | 说明 |
| --- | --- | --- |
| 情境应用题 | 小明有 5 个苹果，吃了 2 个，还剩几个？ | 文字 + 图示双通道 |
| 看图列式 | 图上 3 只鸟 + 飞来 2 只 → □+□=□ | 图形用 SVG/emoji 绘制，离线可用 |
| 比多比少 | 男生 6 人，女生 4 人，男生比女生多几人？ | 强调"相差" |
| 排队问题 | 小明从前数第 3，从后数第 4，队里共几人？ | 思维题 |
| 逆向思考 | 树上一些鸟，飞走 3 只还剩 2 只，原来几只？ | 教材第五单元难点 |
| 多余条件 | 给 3 个数据，只有 2 个用得上 | 审题训练 |
| 找规律 | 1、3、5、（ ）、9 | 图形/数字 |
| 图形拼搭 | 用 2 个正方体能拼成什么 | 空间想象 |

> **计算题配比红线**：每个数学节点纯算式题 ≤ 1 题（≤20%），其余必须是需要读懂情境或看图思考的题。

**写字（3~5 字 / 约 8 分钟，线下）**

按教材「写字表」顺序出字，优先当天语文课文里的字。每个字提供：田字格范字 + 笔顺分步（用 SVG 静态分步图，不做动画）+ 组词一个。孩子在本子上每字写一行，家长拍照上传后评分。

### 4.6 单节点题目配比（一年级上册·标准节奏）

| 模块 | 题量 | 时长 | 交互 | 判分 |
| --- | --- | --- | --- | --- |
| 认字 | 5 | 5 min | 单选 / 连线 | 自动 |
| 拼音 | 6 | 6 min | 单选 / 听音 | 自动 |
| 数学 | 5 | 11 min | 单选 / 数字键盘填空 | 自动 |
| 写字 | 3~5 字 | 8 min | 线下书写 + 拍照 | 家长评分 |
| 打卡 | — | 1 min | 一键完成 | — |

合计 **约 30 分钟**。家长可在设置里整体缩放（轻 20 分钟 / 标准 30 分钟 / 加量 40 分钟），按比例调整题量。

### 4.7 内容生产流水线（本项目最大的工作量，必须先定流程）

```
① 教材原题采集 → ② 变式生成 → ③ 难度标注 → ④ 审核 → ⑤ 入库打包
```

**① 采集**：以教材"练一练"和《教师教学用书》上的例题为原型，人工整理成结构化条目，标注 `unitId / lessonId / nodeId / 知识点 / 原题页码`。**保留原题出处**，方便家长核对"这是课本第几页的题"。

**② 变式（5 条规则，保证"相似但不重复"）**

1. 换数量：5 个苹果 → 7 个苹果（保持同数量级，不超纲）
2. 换情境：苹果 → 气球 / 小兔 / 铅笔（贴近一年级生活）
3. 换问法：求剩余 → 求原有（正向 ↔ 逆向）
4. 换表征：文字 → 看图 / 看图 → 文字
5. 加干扰：增加一个用不上的条件（仅 L3 难题使用）

**③ 难度标注**：`L1 基础（照例题）`、`L2 变式（换数换情境）`、`L3 挑战（逆向/多步/干扰）`。每节点按 **L1:L2:L3 = 3:5:2** 配比。

**④ 审核 checklist**：答案唯一、无歧义、不超纲（不出现未学过的字/概念）、题干字数 ≤ 25 字、图形可离线绘制、无敏感内容。

**⑤ 入库**：输出 `content/{bookId}-{subject}.json`，带 `version` 与 `checksum`，随应用一起发布。

**工作量估算**：每节点 = 语文 11 题 + 数学 5 题 = **16 题**；全册 70 + 44 个节点 ≈ **990 题**。

> **MVP 建议只做**：语文第一~二单元（18 节点 / 198 题）+ 数学第一~二单元（20 节点 / 100 题）≈ **300 题（约 3 周量）**，先把体验跑通，再按周补内容。

## 5. 每日任务与打卡机制

### 5.1 一次打卡的完整流程

```
打开 → 今日任务页（看到 4 张卡片的进度）
  → 认字 5 题 ──→ 拼音 6 题 ──→ 数学 5 题
  → 写字页：看范字 → 本子写 → 拍照上传
  → 打卡完成页：星星动画 + 连续天数 + 明日预告
  → （家长稍后）家长中心 → 待批改 1 条 → 打分
```

### 5.2 任务生成算法

```
todayTask(kid):
  p = progress[kid]
  ywNode = 语文内容包[p.ywUnit][p.ywNode]
  sxNode = 数学内容包[p.sxUnit][p.sxNode]
  review = 错题本中 box<=2 且 due<=今天 的题，最多 2 题（占用数学题位）
  writing = 写字表按 p.writingCursor 取 3~5 字
  return { 认字: ywNode.chars, 拼音: ywNode.pinyin,
           数学: sxNode.items(替换 2 题为 review), 写字: writing }
```

- 语文、数学**两条进度线独立推进**（单元数不同，不强绑）。
- 每节点默认 1 天完成；节奏设为"慢"时 1 节点拆 2 天，"快"时 2 节点合 1 天。
- 断签不惩罚：第二天接着昨天的节点继续，只在统计里标记"未打卡"。

### 5.3 打卡判定

| 条件 | 是否计入完成 |
| --- | --- |
| 认字 + 拼音 + 数学三科题目全部提交 | 必要条件 |
| 写字照片已上传 | 必要条件 |
| 家长已批改 | 不必要（影响"质量分"，不影响"完成"） |
| 实际用时 > 45 min | 仍计完成，标记"超时" |

补卡：家长可在家长中心为"昨天"补打卡（每月上限 3 次），用于生病/外出等场景。

### 5.4 复习机制（轻量间隔重复）

- 答错 → 进错题本，`box=1`，次日复习；
- 复习答对 → `box=2`，3 天后复习；
- 再答对 → `box=3`，7 天后复习；
- 连续答对 3 次 → 移出错题本。
- 每周日自动生成「本周复习」节点，只做错题，约 10 分钟。

### 5.5 激励

- 每题正确 +1 星，答错不扣星（第 2 次答对 +0.5 星，避免挫败）；
- 写字评分星级 → 额外星（5 星 +5，4 星 +3，3 星 +1）；
- 连续打卡 7/14/30 天解锁徽章；
- 星星可兑换"乐园装饰"（复用旧项目的成长树思路，纯视觉奖励，不涉及实物）。

### 5.6 巩固节点（解决"内容量 < 天数"）

**问题**：语文有 70 天的新授量，数学只有 44 天；而一学期约 90 个学习日。数学到第 9 周就会"没新题可做"。

**方案**：某科新内容节点用尽时（或遇到单元末复习日、"慢"节奏的空档），系统自动生成**巩固节点**：

1. 从该科已完成单元中挑出**正确率最低的 3 个知识点**（按 `skill` 聚合）；
2. 每个知识点抽 2 题，优先取错题本中 `box ≤ 2` 的题；
3. 题量不足时，用**换数引擎**现生成：模板题带 `vars`（如 `{"a":[1,5],"b":[1,3]}`），本地随机取值并重算答案；
4. 巩固节点**不推进进度**，只在流水里标记 `type:"review"`，不影响"单元完成度"。

> 换数引擎是本项目唯一的"动态出题"，且仍受模板约束（数值区间、答案类型都预先校验），不会超纲、不会算出离谱的数。

## 6. 功能模块设计

### F1 孩子档案

- 支持 1~6 个孩子；字段：`id / name / avatar(emoji) / color / grade / bookId / createdAt`
- 顶栏头像一键切换，切换后所有数据按 `kidId` 重新载入
- 删除孩子需 PIN + 二次确认，并提示"将删除该孩子全部记录"

### F2 教材与节奏设置

- 选册次：一年级上册 / 下册（后续扩展）
- 选起始单元、起始节点（插班/中途使用场景）
- 节奏：轻 20 / 标准 30 / 加量 40 分钟
- 开关：语音朗读、音效、错题复习、写字每天字数（3/4/5）

### F3 今日任务（首页）

- 顶部：问候 + 连续打卡天数 + 今日剩余时长预估
- 中部：4 张任务卡（认字 / 拼音 / 数学 / 写字），显示 `3/5` 这类进度
- 底部：「开始今天的练习」大按钮 → 按顺序串起四个模块
- 已完成后变为「今日已完成 ✓」+ 星星结算

### F4 练习引擎

- **一次一题**，全屏卡片，不可滚动（避免孩子乱滑）
- 题干 28px，选项按钮高 ≥ 64px，横向或纵向自适应
- 每题右上角喇叭按钮，可重复朗读题干和选项
- 提交后立即反馈：对 → 绿色 + 星星飞入 + 短音效；错 → 橙色 + 正确答案高亮 + 一句话解释
- 答错允许"再试一次"，第二次答对给半分
- 顶部进度条显示 `第 3 / 16 题`，右下角"暂停"（家长可中断，状态保留）

### F5 写字与批改

**孩子侧**：田字格大字（含笔顺分步图、组词）→「写好了，拍照」→ 调用 `<input type="file" accept="image/*" capture="environment">` → 前端压缩到长边 1280px / JPEG 0.8 → 存 IndexedDB → 显示缩略图 → 提交。

**家长侧**：待批改列表（按日期倒序，红点提醒）→ 大图查看（可双指缩放）→ 四个维度打分：

| 维度 | 分值 | 说明 |
| --- | --- | --- |
| 笔画正确 | 1~5 星 | 笔顺、笔画有无增减 |
| 间架结构 | 1~5 星 | 是否居中、比例是否匀称 |
| 整洁规范 | 1~5 星 | 字迹清晰、无涂改 |
| 完成度 | 1~5 星 | 是否按要求每字一行 |

→ 可选文字评语（预置 6 条常用语，一键点选）→ 保存。综合分 = 四维平均，进入书写曲线。

### F6 成长与统计

- **打卡日历**：月历热力图（完成绿、部分黄、未打卡灰、补卡蓝）
- **四维雷达**：认字正确率 / 拼音正确率 / 数学正确率 / 写字均分
- **趋势折线**：近 4 周每日正确率、每日用时
- **错题本**：按学科、按知识点聚合，可"重练一次"
- **成就墙**：徽章 + 累计星星 + 累计学习时长

### F7 导出与备份

| 格式 | 内容 | 用途 |
| --- | --- | --- |
| JSON 全量 | 档案、设置、进度、全部答题流水、写字记录（不含图片二进制，含 photoId 引用） | 换设备完整还原 |
| CSV | 每日一行：日期/模块/题数/正确数/正确率/用时/写字字数/写字均分 | 丢进 Excel 做分析 |
| ZIP | JSON + 全部作业照片（`photos/2026-10-30/u3-1.jpg`） | 长期归档、打印留存 |

- ZIP 用**自实现 store 模式**（不压缩，直接拼 ZIP 结构，约 120 行 JS），避免引入外部库。
- 导入：校验 `schemaVersion` 与 `kidId`，同 `date` 冲突时以"保留两者→标记后到者为准"策略合并，并在导入报告里列出被覆盖条目。

### F8 家长锁

- 4 位 PIN，进入家长中心 / 删除 / 导出 / 改设置时校验
- PIN 存 localStorage（哈希后存，避免明文），忘记可"清空全家设置"重置
- 孩子端全程不出现设置入口

### F9 语音朗读

- 优先 `speechSynthesis`（`zh-CN`），语速 0.9
- 兜底：若浏览器无中文语音，降级为"不朗读 + 显示拼音注音"
- 首次使用检测并提示家长"系统缺少中文语音包"（Windows: 设置→时间和语言→语音）

### F10 设置

字体大小（标准/大）、深色模式（家长端用）、清空数据（PIN + 二次确认）、关于与版本号。

## 8. 数据设计

### 8.1 存储分层（关键决策）

| 数据 | 载体 | 理由 |
| --- | --- | --- |
| 档案、设置、进度、答题流水、错题、写字元数据 | localStorage | 体积极小（一年 < 2 MB），同步读写、易于导出 |
| 作业照片（原图 + 缩略图） | IndexedDB | localStorage 5 MB 上限，照片一年约 180 MB |

**容量核算**：照片压缩后约 150~250 KB/张，每天 1 张，一年 365 张 ≈ **70~90 MB**，IndexedDB 配额通常 ≥ 磁盘 10%，够用 5 年以上。

### 8.2 Key 规范

```
wb2_kids                    // [{id,name,avatar,color,grade,bookId,createdAt}]
wb2_active_kid              // "k1730..."
wb2_{kidId}_settings        // {...}
wb2_{kidId}_progress        // {yw:{unit,node}, sx:{unit,node}, writingCursor, dayIndex}
wb2_{kidId}_checkins        // { "2026-10-30": {done, ms, score, late} }
wb2_{kidId}_attempts        // [{id,date,subject,itemId,answer,correct,tries,ms}]  (保留最近 90 天)
wb2_{kidId}_mistakes        // {itemId:{box, wrongCount, lastWrong, dueDate}}
wb2_{kidId}_writing         // [{date, chars:[...], photoId, scores:{...}, note, reviewedAt}]
wb2_{kidId}_stars           // 数字
wb2_schema_version          // 1
```

IndexedDB：库 `wb2-db`，store `photos`，主键 `id`，索引 `kidId`、`date`；存 `{id, kidId, date, blob, thumbBlob, w, h}`。

## 9. 技术方案

### 9.1 技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | **无框架，原生 ES6 + 单向 store** | 单机、体量小、零依赖、双击即用 |
| 构建 | 无（源码即产物） | 避免 Node 环境依赖，方便随时改 |
| 样式 | 原生 CSS + CSS 变量（沿用乐园令牌） | 复用现有视觉 |
| 存储 | localStorage + IndexedDB | 见 8.1 |
| 语音 | `speechSynthesis` | 免资源、离线可用 |
| 图形 | 内联 SVG + emoji | 离线、可控、体积极小 |
| 导出 ZIP | 自实现 store 模式 | 不引第三方库 |

### 9.2 目录结构

```
每日一练/
├─ index.html              # 唯一入口，内联 critical CSS
├─ assets/
│  ├─ app.css              # 全站样式（复用乐园令牌）
│  ├─ app.js               # 路由 + 状态 + 页面渲染
│  ├─ store.js             # 存储层（localStorage / IndexedDB / 导入导出）
│  ├─ content.js           # 内容包合并入口
│  ├─ audio/               # 短音效（正确/错误/打卡）
│  └─ strokes/             # 笔顺分步 SVG
├─ content/
│  ├─ yw-1a.js             # window.CONTENT['yw-1a'] = {...}
│  └─ sx-1a.js             # window.CONTENT['sx-1a'] = {...}
├─ start.bat               # 本地起 http 服务（可选，方便调试）
└─ docs/                   # 本设计文档
```

> ⚠️ **关键技术坑**：双击 `index.html`（`file://` 协议）时 `fetch('content/yw-1a.json')` 会被 CORS 拦截。因此内容包必须**以 JS 形式内联**（`window.CONTENT = {...}`），用 `<script src="content/yw-1a.js">` 加载。这样双开也能跑，不需要起服务器。

### 9.3 兼容与性能

- 目标浏览器：Chrome/Edge 110+、Safari 15.4+（iPad）、微信内置浏览器（X5 内核，需避免可选链等新语法）
- 首屏 ≤ 1 s，总包体 ≤ 1.5 MB（不含照片）
- 一次只渲染 1 道题，题目切换用 DOM 复用，避免长列表
- 图片上传前压缩（canvas 缩放），避免 iPad 4000px 原图卡死

### 9.4 可选增强（v1.1）

- PWA 离线安装（需 https 或 localhost，`file://` 不生效）
- 打印练习单（家长打印纸质版，孩子线下做）
- 写字 AI 辅助评分（需联网 + 家长自备 API Key，默认关闭）

## 13. 风险清单

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| **内容量巨大（约 990 题）** | 上线慢、质量参差 | 分单元增量上线；先做 4 周量（约 450 题）；建审核 checklist |

### 15.1 补练排程（替代原「断签不惩罚」的被动策略）

- 每日容量（场次）：**工作日 1**、**周末 2**、**法定节假日 3**（其中 1 场为当日新内容，其余优先补欠账）。
- `欠账场次 = 已过学习日应完成场次 - 实际完成场次`（≥0）。
- 今日实际场次 = `1 + min(欠账, 容量 - 1)`；欠账全部补完后回到每日 1 场。
- 进度只在完成时推进，因此补练做的是**同一个未完成节点**，不会跳内容。
- 补练场次默认**保留写字但减半（2 字）**，可在设置里关闭补练写字。
- 家长中心显示「当前欠账 N 场，预计 M 月 D 日（下一个节假日）可补完」。

### 15.2 AI 评分接入（对外契约）

```
本应用 --导出--> grading-package.json + photos/*.jpg --> 评分 App --> grading-result.json --导入--> 本应用
```
- 包内每条形如 `{ recordId, kidId, date, chars:[...], image:"photos/xxx.jpg", prompt, schema }`。
- 结果形如 `{ recordId, scores:{stroke,structure,clean,complete}, note, model }`，导入后写入写字记录并标记 `reviewedBy:"ai"`。
- 内置直连通道：家长中心填 `baseURL / apiKey / model`，走 OpenAI 兼容 `chat/completions` 多模态；失败自动回退人工批改，不阻塞打卡。

### 15.3 相对 v0.1 的数据结构微调

- `checkins[date]` 由单条改为 `{ plan:[{slot,type,yw,sx,status,ms,score,photoId}], done }`，以支持一天多场。
- 新增 `wb2_schedule`（排程游标：起始日、已过学习日数）与 `wb2_{kid}_decor`（已解锁虚拟装饰）。
