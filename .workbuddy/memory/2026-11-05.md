## 核查「连续打卡」天数是否随一次提交更新

用户看到左下角头像下「连续打卡 0 天」，问提交一次后重开会不会变成 1。

**结论：数据层没问题，UI 有一个真实的滞后 bug**
- `App.streakOf()` 按 `Store.days()[d].done` 从今天往前逐日累加；今天未完成不算断，从昨天起算。
- `day.done` 由 `Task.completeSlot()` 计算：`plan.every(场次 done 且写字照片已传)`——**一天排多场时必须全部完成才算 1 天**。
- 实测（headless Edge + 固定 user-data-dir 模拟重开）：工作日 1 场，提交后 `day.done=true`、重开侧栏显示 1 天 ✓；3 场日只做 1 场仍是 0。
- **bug**：写字页 → 完成页这条路径里 `completeSlot` 是在 `done.js` 的 `render()` 里调用的，而 `App.render()` 先 `refreshChrome()` 再渲染页面，故完成页侧栏仍是 0（页面里的「连续天数」却是 1）。要再切一次页面才同步。

**修复**
- `app.js`：Store.subscribe 里对 `kid/kids/book/days/stars/settings/progress/restore/import/wipe` 自动 `refreshChrome()`，加 `chromeBusy` 防重入；`notify()` 本身有 try/catch，安全。答一题触发的 `attempts`/照片的 `writing` 不在列表里，不会每答一题重建导航。
- `done.js` / `writing.js`：一天多场时文案改为「这一场打卡成功，今天还有 N 场」「完成第 N 场 ✓」，不再误导成今天已打卡。
- `tools/smoke.html`：新增 3 项断言（按天累加、断一天重新计数、打卡写入后侧栏立刻 +1）；侧栏那条放在异步链末尾 `streakUI()`，因为 `app.js` 的 boot 订阅要等 DOMContentLoaded 才注册，同步主流程里跑会误判。124 → 127 项全过。
- `README.md`：打卡步骤补上多场次口径，冒烟项数同步。

**踩坑**：冒烟页的内联脚本在 DOMContentLoaded 之前同步执行，`Store.subscribe` 还没注册，任何「Store 变更 → 外壳自动刷新」的断言都必须放到异步段（boot 之后）才测得准。

## 改为「提交一场就算一天」

用户接着明确：「因为今天就算打过卡了」。不再要求当天所有场次做完。

**关键设计：拆两个标记，不要直接改 `day.done`**
- `day.done` 保留「当天所有场次完成」的原义（今日页「全部完成」、按钮禁用、家长中心 pill 都靠它）；若直接改成「任一场 done」，今日页会在做完 1 场后锁掉剩余场次。
- 新增 `day.checkedIn` = 任一场完成且该场写字照片齐；`Task.checkedIn(rec)` 统一判定，兼容老数据（无该字段时按 `rec.done` 或「plan 里有一场 done 且照片齐」兜底，不用补数据）。
- `app.js streakOf()`、`growth.js` 日历与 `longestStreak()` 全部改读 `Task.checkedIn`；日历着色调成「已打卡」，title 带 `（1/3 场）`。
- `completeSlot` 同时写两个标记；`day.finishedAt` 改在首次打卡时记（原来等全部完成）。

**别把打卡事实抹掉**
- `Task.rebuild()` / `Task.ensure()` 重排时继承 `checkedIn(old)`。
- `store.js switchBook()` / `jumpTo()` 原来直接删今天记录，会连带删掉 checkedIn；改成留一个 `{plan:[], done:false, checkedIn:true}` 空壳，`ensure` 按新册次/新进度重排并继承打卡标记。
- 这也是冒烟里 `multiBook()` 断言（切下册后题目全部来自下册）能继续过的原因：不能简单「保留整份旧计划」。

**文案**：done.js「今天打卡成功 ✓，想继续还可以做 N 场」；writing.js 已打卡后按钮为「完成第 N 场 ✓」，未打卡时为「完成今天的打卡 ✓」；today.js 加「✓ 今日已打卡」pill；parent.js pill 三态（已全部完成 / 已打卡 / 进行中）。

**验证**：内容自检 ✅、语法全过、冒烟 **138 项 0 失败**（新增 11 项 `checkinSemantics()`，覆盖兼容兜底、缺照片不算、3 场只做 1 场即 +1、但 `done` 仍 false、重排不抹打卡）。浏览器实测：3 场日完成第 1 场 → 完成页侧栏 1 天、今日页仍可「继续第 2 场」、重开 index.html 仍是 1 天。

**改动状态**：本轮 + 上一轮的修复都还没 commit；更早那次 `4f73cfe` 也仍受代理限制没 push。

## 下架 5 类送分题 + 三档节奏题量改 18/25/35

用户口径：「去掉某几类认字题，原因就是太简单。去掉后用其他题型补上，总题量不变」；「20 分钟改 18 道、30 分钟改 25 道、40 分钟改 35 道」。把「总题量不变」理解为**题库总量 781/737/296/306 不变**（家长中心「全库 X 题」看得到），不是每场题量不变——每场题量由第二个任务单独改。

**下架清单（必须连预设里的概念题一起清）**
- 认字：`认字.数笔画`（一共几笔）、`认字.选组词`（能组成哪个词）、`认字.字形结构`（什么结构）。
- 拼音：`gTone`（「x」是第几声）、`gLetterClass`（声母还是韵母）。**易漏**：`py-presets.js` 的 `basic.quiz[0]` 也是「「a」是声母还是韵母？」；`basic.quiz[1]` 的技能名 `拼音.声调` 要改成 `拼音.声调符号`，否则按技能名查禁题会误伤（内容是「一声的 a 怎么写」，属标调，可保留）。

**补位方式**：不引入需新数据的题型，用现有字库的 `st`（笔顺）加 `认字.笔顺中段`（第 N 笔，N 由 `hashStr(字+节点)` 定，2~5）、`认字.笔顺末笔`；干扰项优先取**这个字里其他真实笔画**（`strokeDistractors`），不能靠排除法猜。连同保留的看字选拼音 / 第一笔 / 选偏旁 / 听音选字共 6 种问法。拼音侧把 `blends` 扩成 pairs × 4 声调 + 本课 sm×ym×4 声调，`charPys/pyChars` 扩到全 446 字，`marks` 扩到 sm×复韵母，兜底池够大才能在不重复题干的前提下仍凑满 6 题/节点。认字 `syl` 题干改成「「x」对应下面哪个字？」避免和 `gSyllableChar` 的「「x」是下面哪个字？」撞 `USED_STEM`。

**每场题量**：`PACE` 改成 `{total, mix:{chars,pinyin,math}, writing, min, label}`，18=5+6+7、25=7+8+10、35=9+11+15。一个节点只有 5 认字 + 6 拼音，所以新增 `fillModule()`：先从**已学节点**按 `seededIndex(date#slot#module)` 轮换抽巩固题（不烧新内容、预览稳定），不够再顺着教材取最近的下一课；游标走完全册时 `curIdx` 默认 `nodes.length`（整册算学过），否则会每天抽到同一批题。`pickMath(items,n)` 改成**返回恰好 n 道且内含 1~3 道 cmp**（原来是 n + cmp，会把总题量顶掉）；`ensureCmp` 改成替换而不是追加。删掉 `plus` 额外追加 2 道数学的分支。`wCount` 改用 `cfg.writing`，别再读已变成认字题数的 `cfg.chars`。`PLAN_VERSION` 2 → 3，旧计划自动重排。
